# Wegweiser — External Lexical Source Documentation

This file tracks every external lexical dataset Wegweiser's master lexicon
pipeline is built to consume. Nothing may be imported until it has an entry
here (spec: Phase 6 §3). If a source's license is unclear, it is not used.

---

## Source: `german-nouns` (gambolputty)

- **Source name:** German nouns (`german-nouns`)
- **Source URL:** https://github.com/gambolputty/german-nouns
- **Dataset file:** `german_nouns/nouns.csv`
- **Compiled from:** German Wiktionary (`de.wiktionary.org`), via the
  `wiktionary-de-parser` project (same author)
- **License:** Creative Commons Attribution-ShareAlike 4.0 International
  (CC BY-SA 4.0) — https://creativecommons.org/licenses/by-sa/4.0/
  (Older releases of the same list were CC BY-SA 3.0; current `main` branch
  is CC BY-SA 4.0 per the repository's `LICENSE` file.)
- **Copyright / attribution requirement:** Yes. Any redistribution or
  derivative must credit "German Wiktionary contributors, via
  gambolputty/german-nouns (CC BY-SA 4.0)".
- **Redistribution allowed:** Yes, including modified/derivative form,
  provided attribution is kept and the derivative is shared under a
  compatible (BY-SA-family) license for the portions taken from this source.
- **Modifications allowed:** Yes (ShareAlike permits derivatives).
- **Commercial use allowed:** Yes, CC BY-SA 4.0 does not restrict commercial
  use.
- **What portion of Wegweiser derives from this source:** Noun records only
  (lemma, grammatical gender, plural, full case declension/"flexion" table).
  No definitions, no example sentences, no translations are taken from this
  source — those remain either Wegweiser-original or are sourced/verified
  separately per §50/§48 of the phase spec.
- **Data format:** CSV. Columns (as documented by the project): `pos`
  (part-of-speech tags, e.g. `Substantiv`), `genus` (`m`/`f`/`n`), `lemma`,
  plus per-case/per-number flexion columns (nominative/accusative/dative/
  genitive × singular/plural).
- **File size:** ~19.3 MB, ~90,000–100,000 rows (per project README).
- **Update frequency:** Irregular; regenerated by the maintainer from fresh
  Wiktionary XML dumps (https://dumps.wikimedia.org/dewiktionary/latest).
- **Bulk download available:** Yes, from the URL above — **but not from
  this environment.** See `data/raw/german-nouns-wiktionary/NOTE.md`.
- **Date accessed:** 2026-09-27 (documentation/README only — see note below;
  the full `nouns.csv` itself has NOT been downloaded into this repository).
- **Sample used for pipeline development/testing:** Two lemmas
  (`Fahrrad`, `Stein`) reproduced verbatim from the project's own public
  README as a worked example — small enough, and explicitly published by
  the source's maintainer as an illustrative sample, to reproduce here for
  adapter/pipeline testing under the same CC BY-SA 4.0 terms.

### Status: PARTIALLY VERIFIED — full dataset NOT yet imported

The license is clear and compatible. The pipeline (`tools/lexicon/`) is
built to consume this source's CSV format via `GermanNounsCsvAdapter`.
**The actual 19.3 MB `nouns.csv` file has not been downloaded into this
project**, because this build environment has no outbound network access
for bulk file transfer (see `data/raw/german-nouns-wiktionary/NOTE.md` for
exactly what was and wasn't possible to fetch here). Running the pipeline
at real scale requires downloading `nouns.csv` from the URL above in an
environment with network access, placing it at
`data/raw/german-nouns-wiktionary/nouns.csv`, and running
`node tools/lexicon/run.js --source=german-nouns-csv --input=data/raw/german-nouns-wiktionary/nouns.csv`.

Coverage gap: this source is **nouns only**. It does not cover verbs,
adjectives, adverbs, or function words (spec §12–§15). A second source
adapter is needed for those word classes before the master lexicon can
claim broad coverage; the `SourceAdapter` registry (`tools/lexicon/sourceAdapters.js`)
is designed so a second source can be added without changing the pipeline.
Candidates researched but not yet wired up:

- **kaikki.org / Wiktextract German dump** (tatuylonen) — CC BY-SA + GFDL,
  full multi-POS coverage (nouns, verbs, adjectives, function words,
  senses, forms). Distributed as a single large JSONL file
  (hundreds of MB) at https://kaikki.org/dictionary/German/ — too large to
  fetch in this environment; a strong candidate for a second adapter once
  downloaded elsewhere.
- **`cstr/de-wiktionary-sqlite`** (Hugging Face) — CC BY-SA 4.0, ~970k
  entries, normalized SQLite. Same size problem here.

## Source: kaikki.org Wiktextract (German)

- **Source name:** kaikki.org machine-readable German dictionary
- **Maintainer / tool:** Tatu Ylonen, `wiktextract` — https://github.com/tatuylonen/wiktextract
- **Source URL:** https://kaikki.org/dictionary/German/index.html
- **Underlying data:** English Wiktionary's German-language entries
  (`en.wiktionary.org`), extracted and structured by wiktextract from the
  official Wikimedia XML dump (https://dumps.wikimedia.org/dewiktionary/latest
  is the raw dump; kaikki.org runs wiktextract over the *enwiktionary* dump
  since German-language senses live there too, per kaikki.org's own site).
- **License:** Wiktionary content is dual-licensed **CC BY-SA 3.0/4.0** and
  **GFDL** (Wiktionary's standard terms, https://creativecommons.org/licenses/by-sa/4.0/
  and https://www.gnu.org/licenses/fdl-1.3.html); kaikki.org's extraction
  tooling (wiktextract) is Apache-2.0 licensed but the *data* it extracts
  carries Wiktionary's own license, not the tool's — confirmed by the
  citation notice printed on every kaikki.org page (see below).
- **Copyright / attribution requirement:** Yes — kaikki.org's own page
  footer asks that reuse cite: Tatu Ylonen, "Wiktextract: Wiktionary as
  Machine-Readable Structured Data", Proceedings of LREC 2022, and link
  back to the relevant kaikki.org page(s).
- **Redistribution / modification / commercial use:** Permitted under
  CC BY-SA with attribution and share-alike for the portions taken.
- **What portion of Wegweiser derives from this source:** lemma, part of
  speech, a compact set of grammatical forms (noun genitive/plural; verb
  present-3sg/past/past-participle/auxiliary), IPA pronunciation where
  given, and — unlike the `german-nouns` source — English glosses and at
  most one short, real example sentence per sense, reproduced under the
  same CC BY-SA terms.
- **Data format:** JSONL, one word-sense-group object per line. Full field
  list confirmed directly from kaikki.org's own published per-word pages
  (which display the exact underlying JSON), e.g.
  https://kaikki.org/dictionary/German/meaning/g/ge/gehen.html.
- **File size:** the full German dictionary JSONL is **~1.0 GB**
  (`https://kaikki.org/dictionary/German/kaikki.org-dictionary-German.jsonl`,
  marked deprecated by kaikki.org but still the bulk download at the time
  of writing; per-POS splits exist too, e.g. the verb-only file is
  ~298 MB). kaikki.org's own recommended non-deprecated bulk source is
  https://kaikki.org/dictionary/rawdata.html (the *raw* wiktextract JSONL,
  used by third parties such as the QubitPi/wiktionary-data HF dataset).
- **Bulk download available:** Yes, from the URLs above — **but not from
  this environment**: both direct file fetch and page-by-page fetching hit
  hard size/robots limits here (see `data/raw/kaikki-wiktextract/NOTE.md`).
- **Sample used for pipeline development/testing:** Two real entries,
  `Wiki` (noun) and `gehen` (verb), fetched directly from kaikki.org's own
  published per-word pages on 2026-09-27 and reproduced here in the same
  JSONL shape kaikki.org itself publishes.
- **Date accessed:** 2026-09-27.

### Status: LICENSE VERIFIED, ADAPTER BUILT, FULL DATASET NOT IMPORTED

Same situation as `german-nouns`: this is by far the stronger source for
Phase 6B's "broad POS coverage" requirement — a single word-sense object
here can carry noun gender, verb conjugation, adjective comparison, real
glosses, IPA, and example sentences all at once, across every part of
speech, not nouns only. But the only two records actually pulled into this
repository are the two named above, fetched one page at a time because
neither the sandbox's bash network (blocked entirely — see the network
test below) nor `web_fetch` (blocked by response-size limits over ~48 MB,
and by robots.txt on the plain file host) could retrieve the bulk file.

**Network test performed this phase**, from inside the sandbox:
```
$ curl -s -m 8 -D - https://raw.githubusercontent.com/gambolputty/german-nouns/master/german_nouns/nouns.csv
HTTP/2 403
x-deny-reason: host_not_allowed
Host not in allowlist: raw.githubusercontent.com. Add this host to your network egress settings to allow access.
```
The same `host_not_allowed` result came back for every other candidate
host tried (`github.com`, `huggingface.co`, `cdn.jsdelivr.net`,
`dumps.wikimedia.org`, `kaikki.org`, `pypi.org`, `codeload.github.com`).
The sandbox's outbound egress is allow-listed and empty for this task.

## Source (researched Phase 10, NOT acquired): QubitPi/wiktionary-data

- **Source URL:** https://huggingface.co/datasets/QubitPi/wiktionary-data
- **Underlying data:** Wiktextract extraction of English Wiktionary's
  German-language entries (same upstream as the kaikki.org source above,
  independently re-packaged).
- **License:** Apache License 2.0 (the wrapper/extraction code and
  packaged dataset; the underlying Wiktionary content itself remains
  CC BY-SA/GFDL per Wiktionary's own terms — both apply).
- **Config/split (confirmed via the dataset's README, Phase 10):**
  `config_name: Wiktionary`, `split: German`, file
  `german-wiktextract-data.jsonl`.
- **File size:** ~186–188 MB (LFS-tracked on Hugging Face).
- **Status: NOT acquired.** Two access paths were tried this phase:
  1. Direct file resolve (`.../resolve/main/german-wiktextract-data.jsonl`)
     — same 186 MB LFS problem as kaikki.org's bulk file (Phase 6B/7).
  2. Hugging Face's `datasets-server.huggingface.co/rows` paginated API
     (returns small JSON pages without downloading the full file) — the
     exact `config`/`split` parameters were identified this phase, but
     `web_fetch` in this environment refuses any URL that hasn't
     *already appeared verbatim* in a prior search/fetch result, and no
     indexed page links that exact query-string URL. `bash`'s egress is
     still a closed allow-list (confirmed again this phase — see
     PHASE10_REPORT.md for the fresh test output). This closes off what
     had looked like a promising paginated-access route.
- **Recommendation for a future phase/networked machine:** either the
  `datasets` Python library (`load_dataset("QubitPi/wiktionary-data",
  "Wiktionary", split="German")`) or a direct HTTP GET on
  `datasets-server.huggingface.co/rows?dataset=QubitPi%2Fwiktionary-data&config=Wiktionary&split=German&offset=0&length=100`
  (paginate `offset` in steps of 100) would work fine from an environment
  with normal network access, avoiding the 186 MB download entirely.

## Phase 12 — ACQUIRED AND IMPORTED

The user uploaded the real dataset directly (4 files, `kaikki_part_1.jsonl`
… `kaikki_part_4.jsonl`, ~1.08 GB / 371,261 lines total) — the same
kaikki.org Wiktextract/German-Wiktionary source documented above, this
time actually in hand rather than blocked behind network access.
**Processed and merged into the master lexicon this phase.** See
`PHASE12_REPORT.md` for the full run log, exact counts, and a real
data-quality issue found and fixed in these files (a pervasive cp1252/
UTF-8 double-encoding corruption affecting ~15–24% of records' non-ASCII
characters — see `tools/lexicon/mojibake.js` and
`data/raw/wiktextract-german/NOTE.md`). License unchanged: CC BY-SA +
GFDL, per Wiktionary's standard terms, attribution as already documented
below under "Attribution to surface in the app".

## Phase 11 acquisition attempt — new findings, still blocked

Phase 11's brief was explicitly "don't repeat the same blocked endpoint —
try other legitimate mechanisms." Five genuinely new mechanisms were
tried (beyond everything in Phases 6B/7/8/10):

1. **npm registry via `npm install`/`npm view`** — `403 Forbidden` from
   `registry.npmjs.org`, same egress proxy as everything else. Rules out
   "install a package that bundles a German wordlist" as a workaround.
2. **pip via `pip download`** — no index reachable (same proxy), rules out
   the equivalent PyPI-package route.
3. **kaikki.org's per-part-of-speech bulk JSONL files for the SMALL
   categories** (conjunctions: 263 kB, particles/articles/determiners
   similarly tiny) — confirmed these exist and are far under any size
   limit. **New, more precise finding:** the blocker for `.jsonl` files in
   this environment's `web_fetch` is content-type-based binary detection
   (the server sends `application/octet-stream` for `.jsonl`), **not
   file size** — a 263 kB file was refused exactly like the 1 GB one,
   returned as `[binary data]` with no text extracted. This narrows down
   exactly what a networked environment needs to not worry about (size is
   fine; just don't rely on this tool's text extraction for `.jsonl`).
4. **Kiwix/ZIM static mirrors of Wiktionary** (e.g. `kiwix.lema.org`,
   `*.freedombox.rocks`) — real, legitimate, browsable per-word HTML
   pages exist. Not pursued at scale: this has the identical per-word
   fetch-call scaling problem as kaikki.org's own per-word pages (already
   used for the 2-record Phase 6B sample), and these particular mirrors
   index the combined English Wiktionary, not the dedicated German
   Wiktionary edition — a real source, but not a shortcut past the
   scaling problem.
5. **A text-extraction proxy pattern (`r.jina.ai/<url>`)** as a way around
   the `.jsonl` binary-detection issue in (3) — blocked by this
   environment's own `web_fetch` permission check, which refuses any URL
   that hasn't appeared verbatim in a prior search/fetch result, even a
   URL built by following an exactly-documented, legitimate public
   pattern for a real third-party reader service.

**Conclusion: still a VERIFIED BLOCK**, with strictly more precise
diagnostics than Phase 10 had. Nothing about the source's size, license,
or legitimacy is the obstacle at this point — every obstacle found is a
property of this specific sandboxed tool environment. See
`PHASE11_REPORT.md` for the full acquisition log and the exact commands a
networked environment should run.
