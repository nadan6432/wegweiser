## Remaining Gaps (honest)

1. **Scale.** The master lexicon has 2 lemmas, not thousands. Running
   `node tools/lexicon/run.js --source=german-nouns-csv --input=<real nouns.csv>`
   on a machine with normal network access is the entire remaining step
   for noun coverage at real scale — no code changes needed.
2. **Word-class coverage.** Only nouns. Verbs, adjectives, adverbs, and
   function words need a second `SourceAdapter` (candidates identified
   and license-checked in `SOURCE_LICENSE.md`: kaikki.org Wiktextract,
   `cstr/de-wiktionary-sqlite`) — the registry pattern in
   `sourceAdapters.js` is built for this but no second adapter is written.
3. **Dictionary UI.** `MasterLexiconService` is not wired into `app.js`'s
   Dictionary screen or `Registry.apply()`/`VOCAB`. Doing that with only
   2 dictionary-only words would misrepresent scale (spec §79); it should
   happen once gap #1 is closed.
4. **Meanings/senses/examples/pronunciation.** None of these exist for
   this source (it's grammar-only data) and none were fabricated
   (spec §25/§46/§50) — a future source (or curated authoring) is needed
   to populate them.
5. **Header-row verification.** The CSV column names the adapter expects
   are inferred from the source's published *parsed output*, not from
   inspecting the real file's actual header row directly (which this
   environment couldn't fetch) — worth a quick diff against the real
   file's first line before a production run.
